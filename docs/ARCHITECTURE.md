# Architecture and capture contract

```text
Phone apps → WireGuard UDP → local mitmdump → selected JSON/JSONP → local JSONL
                                      ↑                          ↓
                   loopback dashboard / stdio MCP         export / agent read
```

The root project is named `POCKETPort`; plugin ID is `pocketport`. `plugins/pocketport/src/pocketport` contains the Python package. The Claude/Codex manifests ship the collection Skill. Local MCP registration is separate and uses the interpreter path generated by the installer, so plugin cache relocation cannot silently change the capture runtime.

## Collection lifecycle

The dashboard's fixed loopback port provides a single-instance guard. The MCP host owns the dashboard and a child mitmdump process. `start_capture` snapshots the selected hosts into a fresh UUID session, generates local keys/CA if absent, starts WireGuard, waits for the addon readiness file, and arms a time limit. Stop or normal host shutdown terminates the child. An unexpected engine exit is reflected by the next status request. A force-killed parent can leave a child running; stop the orphan mitmdump process and disconnect phone WireGuard before restarting. Startup never kills unrelated processes.

TLS selection happens at ClientHello using SNI or an explicitly configured IP. This avoids relying solely on `--allow-hosts` domain matching in a transparent mode where the connection address may be an IP. Hostname matching uses an exact host or a dot-separated subdomain boundary. Unrelated TLS is passed through, and storage applies an independent host filter.

Response recording accepts JSON and JSONP from JSON/plain/JavaScript content types. Media/HTML/non-JSON are skipped. Request bodies and header sets are not persisted. Every URL query value is removed; a recursive known-key filter minimises response credentials. It is deliberately not a general-purpose anonymisation guarantee. Signed requests are never replayed.

mitmproxy streams large responses and enforces a 2 MB HTTP body limit. An individual saved response is limited to 1 MB; streamed bodies may be recorded with null content and `omitted_reason`. Unknown-length or excessively large transfers may be terminated by the engine limit and appear as errors. The 100 MB session cap stops saving, while the user stops the tunnel or its timer expires.

## Record schema, version 1

| Field | Meaning |
|---|---|
| `schema_version` | `1` |
| `captured_at` | UTC ISO time |
| `source` | User-selected preset; not inferred business purpose |
| `host` | Observed request host |
| `method`, `url`, `status` | Request method, query-minimised URL and response status |
| `content_type` | Server-declared content type |
| `response_body` | Credential-minimised JSON value, or null |
| `omitted_reason` | Why body was omitted, or null |

`export.json` contains `schema_version`, session metadata and `records`. Response counts do not equal order counts. MCP pagination is bounded to 20 records and about 120,000 characters; a single larger response returns metadata with a notice to use the file export. `next_offset` refers to the next response record. Live reads retry incomplete final lines. Only stopped sessions can export.

## Migration from the private prototype

This package preserves the WireGuard collection technique, local phone browsing, target host filtering and JSON capture. It removes personal addresses, account numbers, stored profiles, historical captures, static IP assumptions, copied key material, credential replay and reconciliation code. The old prototype's successful sessions establish historical feasibility, not universal current App compatibility. The public release needs real-device testing for each App/OS/version combination.
